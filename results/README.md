# results — what each file shows

Generated by `pipeline/` and `control/`. Small enough to commit, so a teammate can read
the outcome without running a 30-minute solve. The heavy artefacts — point clouds, the
COLMAP database, extracted frames — stay in `out/`, which is gitignored.

## world3 — three clips of one room, solved together

Source: `IMG_7373.MOV`, `IMG_7374.MOV`, `IMG_7375.MOV`. One iPhone 13, 60.8 s total, all
three shot within 68 seconds of each other. One camera means **one shared calibration**,
which [`docs/robot1-reconstruction.md`](../docs/robot1-reconstruction.md) §3 measured as
the difference between a 0.5% and a 65% merge error.

| File | Shows |
| --- | --- |
| `report.json` | Did the clips fuse, and was it worth it. The numbers below. |
| `joint_preview.png` | The fused cloud from three angles, camera paths coloured per clip. |
| `map2d.json` | The 2D occupancy grid. 119 x 91 cells, 45 pushable units. |
| `map2d.png` | That grid as a picture. Orange pushable, grey static, light free, dark unknown. |
| `sim.png` | Two robots on that map. Red and blue are the driven paths; green ring is the goal. |
| `sim_trace.json` | Every pose and event from the run. Paths subsampled 10 Hz → 2 Hz. |
| `frame_selection.json` | How much sharpness the frame picker bought, per clip. |

### What `report.json` says

- **179 of 183 frames registered into one model**, 0.52 px mean reprojection error.
  Per clip: 7373 85/85, 7374 36/40, 7375 58/58.
- **2,690 cross-clip frame pairs verified.** 18.7% / 24.9% / 35.5% for the three clip
  pairs. Verification is the real test — a pair survives only if a consistent two-view
  geometry explains it.
- **9,333 points were triangulated by more than one clip.** Those exist because
  independent passes agreed on them.
- **Floor coverage 4,705 cells against 2,743 for the best single clip: +72%.** Measured
  inside the joint model, so all four rows share one scale.

The headline result is not in the JSON: **IMG_7374 cannot stand on its own.** Solved
alone it fragments into two unrelated models, 22 frames and 15. Layered with the other
two it registers 36 of 40 into the single joint world. Layering rescued a clip.

### What `sim.png` shows

`box2` alone gates 84 cells. A robot identifies it by deleting it and re-flooding, pushes
it clear, the field re-floods, and the route opens. **1 of 2 robots reached the goal.**
The second spent the run exploring and did not arrive — free space on this map is
fragmented into 106 components, and a sparse cloud does not give a second robot a clean
route. That is a limit of the map, not of the loop.

### What has no number

**Scale.** Every distance here is a model unit. Monocular SfM cannot recover a metre. A
tag of known printed size, or one measured baseline, is the only fix.

**The solved focal is not calibration.** 1682.7 px for a 1080x1920 frame, a 59.4° field
across the long side — the right region for an iPhone 13 in video crop, which is a
plausibility check, not a measurement. This repo has twice been burned trusting a solved
focal.
